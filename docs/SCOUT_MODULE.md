# Модуль D — Авто-скаут (внутренний, только для владельца)

> **Статус:** ТЗ / проектирование  
> **Аудитория:** только владелец продукта (ilari), **не** для пользователей бота  
> **Связанные документы:** [PRODUCT_STATUS.md](./PRODUCT_STATUS.md) · [ROADMAP.md](./ROADMAP.md) · [TECHNICAL_SPEC.md](./TECHNICAL_SPEC.md) · **[SCOUT_CRM.md](./SCOUT_CRM.md)**

---

## 1. Зачем этот модуль

Автоматизировать **привлечение клиентов** на Pulse AI без ручной работы:

- искать целевые Telegram-каналы по нишам;
- писать владельцам в личку с персонализированным оффером;
- наблюдать в чатах/каналах ниши и копить разведданные для LLM;
- **учиться на практике**: какие формулировки и офферы дают ответ, а какие игнор/бан;
- подсказывать владельцу, что ответить, если диалог перешёл в «ручной режим».

Цель — чтобы программа **работала на владельца 24/7**, а ИИ улучшал конверсию со временем.

---

## 2. Два типа скаутов (4–8 аккаунтов суммарно)

| Тип | Кол-во | Роль | Риск |
|-----|--------|------|------|
| **Observer** (наблюдатель) | 2–4 | Сидят в чатах/каналах ниши, читают поток, LLM извлекает паттерны (воронки, акции, крючки, тон) | Низкий (пассивное чтение) |
| **Outreach** (исходящий) | 2–4 | Ищут каналы, пишут владельцам в ЛС, ведут скрипт до ответа или эскалации | Высокий (спам, баны) |

**Принцип разделения:** observer-аккаунты не пишут незнакомым — меньше шанс потерять всё разом. outreach-аккаунты — расходный материал с ротацией и антиспамом.

---

## 3. Авто-скаут: ежедневный пайплайн (Outreach)

### 3.1. Расписание

- **1 раз в сутки** (настраиваемое окно, напр. 10:00–14:00 МСК) — фоновый job `ScoutDailyRun`.
- Лимиты на прогон: не более **N новых ЛС в сутки на аккаунт** (старт: 5–15, калибровка по банам).

### 3.2. Поиск каналов

**Источники (приоритет):**

1. **TGStat API** `channels/search` — по `category` + `q` (ключевые слова), `country`, `language`.
2. Резерв: собственная база уже проанализированных каналов (Модуль A).
3. Резерв: парсинг каталогов / ручной импорт CSV.

**Ключевые слова и тематики (конфиг `scout.keywords`):**

```yaml
scout:
  topics:
    - smm
    - бизнес
    - саморазвитие
    - финансы
    - маркетинг
    - инфобизнес
    - фриланс
    # расширяемый список
```

**Фильтры отбора канала:**

| Параметр | Значение |
|----------|----------|
| Подписчики | **5 000 – 50 000** |
| Тип | `channel` (не чат) |
| Язык | русский (по умолчанию) |
| Уже контактировали | исключить (таблица `scout_contacts`) |
| Чёрный список | исключить (ручной + авто после жалоб) |
| Качество | не пустой канал, ≥3 поста за 30 дней (если данные есть) |

### 3.3. Первое сообщение в ЛС

- Шаблоны в БД `scout_message_templates` (A/B варианты).
- Перед отправкой **LLM-персонализация** одной строки: название канала, ниша, 1 факт из анализа (если канал уже в базе).
- Жёсткий лимит длины: ≤ 400 символов, без ссылок в первом сообщении (снижение спам-скора).
- **Задержки:** случайный интервал 45–180 сек между отправками; не более 1 ЛС в 2 мин на аккаунт в пике.

**Пример структуры шаблона (не финальный текст):**

```
Привет! Веду {channel_title} — заметил, что у вас сильные посты про {topic},
но охват мог бы быть выше. Мы как раз делаем бота, который за минуту разбирает
канал и даёт 3 идеи под ваш стиль. Могу скинуть бесплатный разбор — интересно?
```

### 3.4. Ответ получен → «ручной режим»

| Событие | Действие |
|---------|----------|
| Входящее сообщение от контакта | `scout_leads.status = REPLIED`, outreach-бот **перестаёт** слать авто-ответы |
| Уведомление владельцу | Сообщение в **админ-чат** / личку владельца с контекстом + кнопки |
| LLM-подсказка | 2–3 варианта ответа (коротких), с учётом истории и что сработало в прошлом |
| Режим «продолжить скрипт» | Владелец жмёт кнопку → бот шлёт следующий шаг скрипта (опционально) |
| Режим «я сам» | Владелец отвечает с телефона; скаут только логирует исход |

## 4. Observer-скауты (разведка в чатах)

### 4.1. Что делают

- Подписаны на **публичные чаты и каналы** ниш (список `scout_watch_sources`).
- Не пишут в ЛС и не спамят.
- Раз в N часов батчем отдают новые сообщения в LLM:
  - тип контента (акция, воронка, кейс, продающий пост);
  - крючок в первой строке;
  - CTA;
  - оценка «сильно / слабо» (1–5).

### 4.2. Куда складывается

- Таблица `scout_intel_events` → агрегатор → **база знаний ниш** (Модуль A).
- Используется в: анализе каналов для клиентов, подсказках outreach-LLM, отчёте владельцу «что сейчас заходит в нише».

## 5. Антиспам и выживаемость аккаунтов

### 5.1. Поведенческие лимиты

| Правило | Значение (старт) |
|---------|------------------|
| Новых ЛС / день / аккаунт | 5–15 |
| Пауза между ЛС | 45–180 сек (random) |
| «Тёплый» старт нового аккаунта | 3 дня: только чтение, 0 исходящих |
| Одинаковый текст | запрещён (A/B + LLM-вариация) |
| Повтор контакта | never (unique constraint) |

### 5.2. Мониторинг бана / flood

- Детект: `FloodWait`, `USER_BANNED_IN_CHANNEL`, `PEER_FLOOD`, отсутствие `getUpdates`.
- Аккаунт → статус `scout_accounts.status = BANNED` или `FLOOD_WAIT`.
- **Авто-пауза** outreach на этом аккаунте на `retry_after` + буфер.
### 5.3. Интеграция с антиспам-ботом Telegram

> В Telegram есть служебные боты (напр. `@SpamBot`), куда нужно написать `/start` после ограничений.

**Требование в ТЗ:**

- При статусе `RESTRICTED` outreach-аккаунт **автоматически** (или с подтверждением владельца) отправляет `/start` в `@SpamBot`.
- Логируется в `scout_antispam_actions`.
- Если после проверки ограничение снято — аккаунт возвращается в пул с пониженным лимитом на 7 дней.
- **Реализация:** отдельный `ScoutAntispamService` + очередь задач; для MTProto-аккаунтов — через TDLib/Telethon, не через Bot API (боты не пишут в SpamBot от имени user).

### 5.4. Ротация аккаунтов

- Пул `scout_accounts`: phone/session, тип (observer/outreach), прокси, статус, daily_sent_count.
- Round-robin по здоровым аккаунтам; выгоревший уходит в карантин.

## 6. Обучение на практике (feedback loop)

### 6.1. Что логируем на каждый исходящий контакт

| Поле | Описание |
|------|----------|
| `template_id` | какой шаблон |
| `variant` | A/B |
| `personalized_hook` | что подставил LLM |
| `channel_niche` | ниша |
| `channel_subs` | подписчики |
| `sent_at` | время |
| `outcome` | `NO_REPLY` / `REPLIED` / `POSITIVE` / `NEGATIVE` / `BLOCKED` / `BANNED_US` |
| `reply_latency_sec` | как быстро ответили |
| `converted` | дошёл до /start бота или оплаты |

### 6.2. Как «учится» система

1. **Еженедельный отчёт LLM:** какие шаблоны/ниши дают лучший reply rate.
2. **Авто-понижение веса** слабых шаблонов (< 5% ответов при n ≥ 20).
3. **Предложение новых формулировок** владельцу на утверждение (не автопубликация в прод).
4. **Контекст в подсказках:** при ответе лиду LLM видит топ-3 успешных диалога прошлой недели в той же нише.

> Fine-tune модели **не делаем** — достаточно RAG + статистика исходов + промпт с бенчмарками.

## 7. Админ-панель (внутри бота, только owner)

Команды / меню **только для `telegram_id` владельца** (`scout.admin-ids` в конфиге):

| Команда | Действие |
|---------|----------|
| `/scout_status` | Аккаунты, лимиты, баны, отправлено сегодня |
| `/scout_pause` / `/scout_resume` | Стоп/старт outreach |
| `/scout_leads` | Активные диалоги (ручной режим) |
| `/scout_suggest` | LLM-подсказка ответа по lead_id |
| `/scout_report` | Недельная статистика конверсии |

Уведомления: «🔔 Лид ответил: @channel_owner — [превью]» + inline «Подсказать ответ» / «Я сам».

## 8. Архитектура (технически)

```
┌─────────────────────────────────────────────────────────────┐
│                    Pulse AI (Spring Boot)                    │
├─────────────────────────────────────────────────────────────┤
│  ScoutScheduler (daily)                                     │
│    → ChannelDiscoveryService (TGStat search + filters)      │
│    → LeadQueueService                                       │
│    → OutreachWorker (per scout account, delays)             │
│                                                             │
│  ObserverIngestService (MTProto/TDLib sidecar)               │
│    → IntelExtractionService (LLM batch)                     │
│    → NicheKnowledgeService (Module A)                       │
│                                                             │
│  ScoutConversationService                                   │
│    → on inbound DM: pause bot, notify admin, LlmSuggest     │
│                                                             │
│  ScoutAntispamService                                       │
│    → flood/ban detect → SpamBot /start, quarantine         │
│                                                             │
│  ScoutAnalyticsService                                      │
│    → template scoring, weekly report                        │
└─────────────────────────────────────────────────────────────┘
         │                              │
         ▼                              ▼
   Bot API (@Pulsse_AI_bot)      MTProto accounts (4–8)
   (продукт для клиентов)        (скауты — отдельные сессии)
```

**Важно:** исходящие ЛС **невозможны** через обычный Bot API. Нужен **user-account слой**:

- **TDLib** (Java binding) или **Telethon** sidecar (Python microservice + REST/gRPC).
- Отдельные SIM/номера, прокси SOCKS5 на аккаунт.
- Сессии хранить зашифрованно (`scout_sessions`), не в git.

## 9. Схема БД (черновик)

```sql
-- Аккаунты-скауты (user sessions, не боты)
scout_accounts (
  id, label, type ENUM('OBSERVER','OUTREACH'),
  phone, session_encrypted, proxy_host, proxy_port,
  status ENUM('ACTIVE','PAUSED','FLOOD_WAIT','BANNED','WARMUP'),
  daily_limit, sent_today, last_sent_at, banned_at, created_at
);

-- Найденные каналы-кандидаты
scout_prospects (
  id, username, title, niche, subscribers,
  tgstat_channel_id, discovered_at, source,
  status ENUM('NEW','QUEUED','CONTACTED','SKIPPED','BLACKLIST')
);

-- Исходящие контакты и диалоги
scout_contacts (
  id, prospect_id, scout_account_id, template_id,
  personalized_text, sent_at,
  status ENUM('SENT','REPLIED','MANUAL','CONVERTED','BLOCKED'),
  outcome, reply_at, converted_at
);

-- Шаблоны первого касания
scout_message_templates (
  id, name, body_template, weight, reply_rate,
  is_active, created_at
);

-- Сообщения диалога (для LLM-контекста)
scout_messages (
  id, contact_id, direction ENUM('OUT','IN'),
  text, sent_at
);

-- Observer: сырые инсайты из чатов
scout_intel_events (
  id, watch_source_id, raw_excerpt, intel_json,
  extracted_at
);

-- Антиспам действия
scout_antispam_actions (
  id, scout_account_id, action, result, created_at
);
```

## 11. Этапы разработки

| Фаза | Срок | Результат |
|------|------|-----------|
| **D0** | 3 дня | Схема БД, конфиг, admin-only guard, `/scout_status` заглушка |
| **D1** | 1 нед | TGStat discovery + фильтр 5–50k + очередь prospects |
| **D2** | 2 нед | MTProto sidecar: 1 outreach-аккаунт, ручной триггер отправки |
| **D3** | 1 нед | Шаблоны + LLM-персонализация + задержки + лог исходов |
| **D4** | 1 нед | Inbound → ручной режим + уведомление + LLM-подсказка |
| **D5** | 1 нед | 2–4 outreach + 2 observer, ротация, антиспам SpamBot |
| **D6** | 1 нед | Аналитика шаблонов, weekly report, A/B веса |
| **D7** | 2–3 нед | **Scout CRM:** веб-inbox, ответы через сайт, AI-подсказки — [SCOUT_CRM.md](./SCOUT_CRM.md) |

**Итого:** ~6–7 нед (скауты) + ~3–4 нед (CRM) после стабилизации MVP продукта.

## 12. Риски и ограничения

| Риск | Митигация |
|------|-----------|
| Бан аккаунтов outreach | Лимиты, прогрев, ротация, отдельные SIM |
| Юридически холодные ЛС | Только РФ-ниша, мягкий оффер, opt-out, чёрный список |
| Telegram ToS | Модуль **только internal**, не продаём как фичу пользователям |
| Стоимость LLM на observer | Батчинг, дешёвая модель, не каждое сообщение |
| `@SpamBot` не снимает бан | Ручная эскалация + алерт владельцу |
| TGStat FREE не даёт search | Платный тариф или альтернативный поиск |
