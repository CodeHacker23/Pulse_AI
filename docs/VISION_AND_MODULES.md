## 1. Суть продукта одной фразой

**Pulse AI** — операционная система админа Telegram-канала:

**анализ стиля → контент под канал → планировка → ассистент-продавец в комментариях**.

Не «ещё один генератор текста» и **не замена статистики Telegram**.  
Обещание: **меньше рутины на контенте, больше заявок из комментариев** — без ухода из Telegram.

### Три столпа продукта

| Столп | Что даём | Роль |
|-------|----------|------|
| **Контент-движок** | Анализ стиля → идеи → пост/опрос → правка → публикация | Вход и retention |
| **Ритм** | Слоты, «🔥», план, следующий пост без сброса | Привычка вести канал из бота |
| **Ассистент** | Лиды, живые ответы, возражения, learnings, CRM | **Главная причина подписки** |

### Метрики — вспомогательный слой (не moat)

У админа в Telegram уже есть **нативная статистика канала**: подписчики, просмотры, графики, источники — точнее, чем наш скрапинг.

**Мы не конкурируем** с этим экраном. Наши метрики нужны для:
- понимания стиля и тем перед генерацией контента;
- сравнения с конкурентом (перк);
- подсказок слотов «🔥»;
- честного среза для публичного канала без админки у бота.

В боте: **короткая сводка + «н/д» без данных + отсылка к статистике канала в Telegram** для тех, у кого бот — админ.

**Human-in-the-loop:** черновики, не истина; факты только из профиля компании; финальные решения — за админом.

## 3. Принцип разработки (важно)

```
СЕЙЧАС                          ПОТОМ (модули)
─────────────────────           ─────────────────────────────
Ядро продукта в боте     →      Obsidian (штаб знаний)
Качество ИИ-агента       →      Web-админка
```

## 7. Целевая архитектура

### 7.1. Telegram-бот (ядро продукта для клиентов)

Рабочее место админа канала. Здесь деньги и retention.

### 7.2. Ассистент = Jarvis для канала (лиды + рассылки + дожим)

Не «умная справка» и не «принеси-подай». **Три режима — все в подписке:**

| Режим | Что делает | Статус |
|-------|------------|--------|
| **Inbound** | Ловит горячие комменты → пинг админу → черновик по профилю компании | ✅ P0.5 |
| **Outbound (рассылки в ЛС)** | Парсит аудиторию (участники чата/группы, свои списки) → персонализированная рассылка в личку → custdev, оффер, приглашение в канал | 🔜 **ключевая фишка модуля**, P1 |
| **Дожим** | Ведёт диалог после ответа: коротко, по скрипту/возражениям; эскалация админу | 🔜 P0.8–P1 |

**Outbound — не опция «на потом», а то, за что платят 3999₽/мес.** Telegram это поддерживает; рынок на этом живёт. Наша задача — дать **управляемый контур**, а не отговаривать от фичи.

#### 7.2.1. Outbound: как это работает у клиента

1. **Источник аудитории:** парсинг участников публичной группы/чата по ссылке; импорт username/id; повторные касания только по whitelist.
2. **Кампания:** шаблон + LLM-персонализация (1 строка под контекст); сценарии: custdev («3 вопроса»), приглашение в канал, мягкий оффер.
3. **Аккаунты:** пул с отлежкой (купленные/прогретые сессии), ротация, лимиты в сутки на аккаунт, пауза при `FLOOD_WAIT` / бане.
4. **Ответ получен →** статус REPLIED, авто-рассылка стоп; дальше **дожим** (агент или админ из бота).
5. **Отчёт в боте:** отправлено / доставлено / ответили / в работе / отказ.

#### 7.2.2. Тарифы рассылок (черновик монетизации)

| Тариф | Цена | Включено |
|-------|------|----------|
| **Ассистент** | 3 999 ₽/мес | Inbound без лимита + **100 исходящих ЛС**/мес + дожим по ответам |
| **Ассистент Pro** | + апсейл / 5 000 ₽ пакет | **до 1 000 ЛС**/кампания + приоритетная очередь |
| **Доп. пакет** | pay-as-you-go | +500 / +1000 контактов |

Публикация постов и «запросы на анализ» — **отдельно** (пакеты запросов). Подписка = **ассистент + рассылки + лиды**.

#### 7.2.3. Техника (общая с internal-скаутом)

Outreach-стек клиента и internal-скаут Pulse ([SCOUT_MODULE.md](./SCOUT_MODULE.md)) — **одна инфраструктура** (аккаунты, очереди, антиспам, шаблоны, CRM). Internal-скаут = мы продаём себя; клиентский outbound = они продают свой продукт.

Успех агента = **заявки, ответы, люди в канале**, не красивые тексты в вакууме.

### 7.3. Obsidian — личный штаб владельца Pulse (модуль, не MVP)

Для **тебя**, не вместо бота клиенту.

| Может | Не стоит ждать |
|-------|----------------|
| Протоколы («как продавать», «чего не обещать») — меняешь файл → бот читает | Fine-tune модели «внутри Obsidian» |
| Карточки каналов, инциденты, learnings, inbox | Замена Postgres (оплаты, статусы) |
| Связи `[[...]]`, граф, Dataview-таблицы | Красивые интерактивные дашборды уровня веб (см. ниже) |
| Отказоустойчивость знаний: диск + git | Realtime multi-user SaaS vault |

**Графики в Obsidian «как в админке» — честно:**

- Нативно Obsidian **не рисует** продуктные графики метрик Pulse.
- Варианты: (a) бот/сервис генерит PNG/SVG и кладёт в vault; (b) Mermaid/датчики в MD; (c) **настоящая интерактивная статистика — в web-админке**, а Obsidian хранит выводы и протоколы.
- Для «умной отказоустойчивой» системы: **БД = факты, Obsidian = устав + выводы, Админка = обзор и рычаги**.

Структура vault (черновик):

```
PulseOps/
  protocols/          # живые приказы агенту и контенту
  playbooks/          # что делать если упал бот / нет лидов / …
  channels/           # карточки (профиль, FAQ, learnings)
  learnings/          # выводы LLM + твои правки
  negotiations/       # разборы удачных/провальных диалогов
  inbox/              # ты кидаешь сырьё → система разбирает
  incidents/          # баги метрик, фейлы публикаций
```

### 7.4. Web-админка владельца (отдельный модуль, после продукта)

Визуальный пульт **оператора Pulse**, не клиента канала:

- сколько стартануло бот / сколько оплатило / конверсия воронки;
- рассылка акций (скидка, TTL, кому);
- настройки бота (фичи on/off, лимиты, тексты);
- статус скаутов, агентов, очередей;
- просмотр sync с Obsidian (протоколы, learnings) — опционально iframe/ссылка.

**Админка читает ту же БД (+ опционально vault).** Obsidian не заменяет админку.

### 7.5. Скауты (уже в доках, внутренний модуль)

Холодный трафик / outreach — см. [SCOUT_MODULE.md](./SCOUT_MODULE.md).  
Связка с ассистентом: скаут приводит → агент/админ дожимает.

### 7.6. Jarvis Growth Stack (полная карта ассистента)

**Jarvis** — не «бот ответов», а **оператор роста канала**: знает нишу → находит людей и площадки → действует → учится.

```
КОНТЕНТ (ядро)  →  публикация в своём стиле
INBOUND (P0.5)   →  горячие комментарии
OUTBOUND (P1)    →  рассылки в ЛС, парсинг групп, invite в канал
RADAR (P1.5)     →  мониторинг чатов, скоринг площадок, Ad Intel
DEALS (P2–P3)    →  переговоры о рекламе, маркетплейс 20%
```

## 8. ИИ-агент: как сделать «не просто ассистента», а продавца

### 8.1. Проблема типичного LLM в чате

- Многословно, канцелярит, «как нейросеть».
- Обещает лишнее.
- Не держит линию переговоров (цена → возражение → следующий шаг).

### 8.2. Как «обучаем» без магии (рабочий контур)

Не ждать, что модель «сама поумнеет в Obsidian». Контур:

```
Наблюдение (комменты/ответы/исходы)
        ↓
Запись факта (БД) + заметка learning (vault)
        ↓
Вывод (коротко, читаемый тобой)
        ↓
Правка протокола (ты) ИЛИ авто-добавление в «книгу возражений»
        ↓
Следующий диалог читает протоколы + похожие кейсы (RAG)
```

| Слой | Содержание |
|------|------------|
| **Протоколы** | Жёсткие рамки: тон, длина реплик (2–4 коротких сообщения), запреты, эскалация админу |
| **Книга компании** | Уже есть задел: профиль / FAQ / «не обещать» |
| **Книга переговоров** | Возражения («дорого», «подумаю») → рабочие ответы, только проверенные |
| **Разбор сделок** | won/lost + почему; ты читаешь; LLM опирается на won |
| **Стиль живой речи** | Few-shot из реальных удачных ответов админа; запрет простыней; разбивка на реплики как в Telegram |
| **Humans-in-the-loop** | Сейчас: черновик + апрув. Позже: авто на FAQ, эскалация на сложное |

### 8.3. Критерии «продавец», а не «болтун»

- Ответ ≤ N предложений / разбит на 2–3 сообщения.
- Всегда следующий шаг (вопрос / слот / ссылка / «напишите X»).
- Ноль цифр вне профиля компании.
- Лог: что спросили → что ответили → статус лида → (позже) выручка.

### 8.4. Лидогенерация (контур ассистента)

Одна воронка, три входа:

1. **Inbound** — комментарии под постами канала (✅).  
2. **Outbound** — рассылки в ЛС: custdev, оффер, invite (🔜 P1, **core подписки**).  
3. **Контент-магнит** — пост в канале → трафик → inbound/outbound добивает.

Inbound и outbound **усиливают друг друга**: рассылка открывает диалог → агент дожимает; комментарий → тот же скрипт возражений.

## 10. Отказоустойчивость (целевой принцип)

| Компонент | Role | Если упал |
|-----------|------|-----------|
| PostgreSQL / H2 | Факты, очереди, деньги | Бэкап + restore; бот в degrade |
| Telegram API | Доставка | Ретеи очереди публикаций |
| LLM | Текст | Fallback / «свяжется админ» |
| Obsidian vault | Уставы и выводы | Диск + git; бот без vault работает на defaults |
| Админка | Обзор | Бот живёт без неё |

## 11. Решения, зафиксированные этим документом

1. **Сначала продукт в Telegram**, админка и тяжёлый Obsidian — модульно позже.  
2. Obsidian = **штаб владельца** (протоколы, learnings, наглядные заметки), не замена админке и не «обучение весов».  
3. Интерактивная статистика и рассылки акций — **в web-админке**.  
4. Главный рычаг роста ценности подписки — **агент-лидоискатель / продавец с человеческой речью и самообучением через протоколы + разборы**.  
6. **Метрики в боте — вспомогательные**; не конкурируем с нативной статистикой Telegram.  
7. Лидогенерация наружу — только после inbound-агента.
