## 1. Задача

Веб-панель (HTML/SPA), через которую вы:

- видите **все диалоги** outreach-скаутов в одном месте;
- отвечаете в ЛС **как в консоли** — без открытия Telegram на телефоне;
- отмечаете **прочитано / непрочитано**, ведёте воронку лидов;
- **не выбиваете** купленные аккаунты с сессии (одно устройство = сервер).

Это аналог админки, которую вам сделали «на 200 уч» — диалоги, кнопка «прочитать», ответ через сайт **под тем же аккаунтом**.

---

## 2. Главное правило: почему не вылетает с номера

| ❌ Так нельзя | ✅ Так надо |
|--------------|------------|
| Зайти в Telegram **на телефоне** на номер скаута | Номер скаута **только на сервере** (MTProto session) |
| Параллельно отвечать с телефона и с сайта | Отвечать **только через веб-CRM** → API → sidecar |
| QR-логин с нового устройства «для проверки» | Одна `.session` файл / TDLib db на аккаунт, бэкап зашифрованный |

**Как работает админка друга:** на сервере крутится **Telethon/Pyrogram/TDLib** с уже авторизованной сессией. Сайт **не логинится в Telegram** — он шлёт HTTP/WebSocket в ваш бэкенд, бэкенд шлёт `send_message` через **ту же** сессию. Для Telegram это одно «устройство» — ваш VPS.

```
Браузер (вы)  →  Scout CRM (Spring)  →  MTProto Sidecar  →  Telegram
                      ↑                        ↑
                 PostgreSQL              1 session / аккаунт
                 (кэш диалогов)          никогда не трогать телефоном
```

## 3. Экраны веб-CRM

### 3.1. Layout (одна страница, как мессенджер)

```
┌──────────────┬────────────────────────────┬─────────────────┐
│  Скауты      │  Список диалогов           │  Чат + CRM      │
│  ● Scout-1   │  🔴 @channel_boss  2 мин   │  @channel_boss  │
│  ○ Scout-2   │  ⚪ @smm_girl      вчера    │  ─────────────  │
│  (статус)    │  🟡 @biz_channel  ждёт     │  [история]      │
│              │  фильтр: горячие / все     │  [консоль ввода]│
│  + метрики   │  поиск                     │  [AI подсказки] │
└──────────────┴────────────────────────────┴─────────────────┘
```

### 3.2. Функции MVP (фаза CRM-1)

| Функция | Описание |
|---------|----------|
| **Inbox** | Все ЛС выбранного скаута, сортировка по времени / непрочитанным |
| **Прочитано** | Кнопка → `readHistory` через MTProto + флаг в БД |
| **Непрочитанное** | Счётчик badge, фильтр «только новые» |
| **Ответ** | Текстовое поле + Enter / кнопка «Отправить» |
| **Статус скаута** | ACTIVE / FLOOD / BANNED, отправлено сегодня / лимит |
| **Карточка лида** | Канал, подписчики, ниша, ссылка на разбор Pulse (если есть) |

### 3.3. CRM-воронка (фаза CRM-2)

Стадии лида (перетаскивание или кнопки):

```
Новый → Ответил → Интерес → Демо / разбор → Оплата → Потерян
```

| Поле | Авто / ручное |
|------|----------------|
| Стадия | AI предлагает, вы подтверждаете |
| Теги | `горячий`, `думает`, `дорого`, `агентство` — AI из текста |
| Следующее действие | «Написать в пятницу», «скинуть кейс» |
| Напоминание | CRM пушит в Telegram вам или в колонку «Сегодня» |

### 4.3. «ИИ ведёт CRM» (не заменяет вас — готовит)

**Режимы:**

| Режим | Поведение |
|-------|-----------|
| **Assist** (старт) | AI только подсказки, отправляете вы |
| **Draft** | AI пишет черновик, вы жмёте «Ок» / правите |
| **Auto-lite** | AI сам отвечает на FAQ (цена, как работает, ссылка); нестандартное → вам в «ручной» |

Переключатель **на уровне диалога**: «этот лид — только я».

### 4.4. Обучение «в поле»

Каждый исход сохраняется:

```json
{
  "template_id": "soft_offer_v2",
  "ai_variant_used": 2,
  "lead_stage_final": "CONVERTED",
  "messages_count": 5,
  "niche": "smm",
  "channel_subs": 12000
}
```

Раз в неделю LLM-отчёт:
- какие формулировки дали reply > 15%;
- какие ниши конвертят в `/start` бота;
- что обновить в шаблонах outreach и в CRM-сниппетах.

## 5. Дополнительные фичи для КПД

### 5.1. Операционные

- **Горячие клавиши**: `Ctrl+Enter` отправить, `1/2/3` — вставить AI-вариант.
- **Сниппеты**: `/разбор`, `/цена`, `/кейс` — заготовки одним словом.
- **Пакетные действия**: отметить 10 диалогов прочитанными.
- **Назначение скаута**: лид закреплён за аккаунтом, который писал первым (не путать контекст).
- **Чёрный список** одной кнопкой → больше не писать с любого скаута.

### 5.2. Интеграция с Pulse AI

| Действие в CRM | Что делает продукт |
|----------------|-------------------|
| «Разбор канала» | Запускает анализ по `@username` лида, результат в карточку |
| «Кинуть отчёт» | Генерирует короткий PDF/ссылку на тизер |
| «Добавить в базу ниш» | Лид + канал → Модуль A |

### 5.3. Уведомления вам

- Browser push при новом ответе лида.
- Дубль в ваш личный Telegram (основной аккаунт, не скаут): «🔔 @user ответил: …» + deep link в CRM `https://scout.yourdomain/chat/123`.

### 5.4. Безопасность админки

- Логин + пароль (или magic link на ваш email).
- IP whitelist (опционально).
- JWT session, HTTPS only.
- **Нет публичного доступа** — только VPN или ваш IP.

## 6. Архитектура

```
┌─────────────────────────────────────────────────────────────────┐
│  Scout CRM Web (React/Vue или Thymeleaf MVP)                     │
│  /scout-admin  —  inbox, chat, CRM board, AI panel               │
└───────────────────────────┬─────────────────────────────────────┘
                            │ REST + WebSocket
┌───────────────────────────▼─────────────────────────────────────┐
│  Spring Boot                                                     │
│  ScoutCrmController · ScoutInboxService · ScoutAiAssistService    │
│  ScoutLeadService (pipeline) · ScoutNotificationService           │
└───────────────────────────┬─────────────────────────────────────┘
                            │ gRPC/HTTP
┌───────────────────────────▼─────────────────────────────────────┐
│  MTProto Sidecar (Python Telethon или TDLib)                       │
│  • 1 process per scout account OR 1 process multiplexer           │
│  • events: NewMessage → webhook to Spring                          │
│  • commands: send_message, mark_read, get_dialogs                │
│  • session file ONLY here — never export to phone                │
└─────────────────────────────────────────────────────────────────┘
```

**Real-time:** sidecar пушит `NewMessage` → Spring → WebSocket → браузер (без опроса каждые 5 сек).

**Синхронизация прочитанного:**
- Входящее → `is_read=false` в БД, badge в UI.
- Вы открыли чат → `mark_read` MTProto + `is_read=true`.
- Кнопка «прочитать без ответа» → только MTProto read, без отправки.

## 10. Чеклист «не убить аккаунт»

- [ ] Скаут-номера **не установлены** на личный телефон после первой авторизации на сервере
- [ ] Один session file на аккаунт, бэкап только offline
- [ ] Прокси sticky (тот же IP на аккаунт)
- [ ] Лимит ручных ответов из CRM: не более 30–50/день/аккаунт
- [ ] Пауза 3–10 сек перед отправкой из CRM (имитация человека)
- [ ] Не открывать Telegram Web/Desktop на номере скаута **никогда**
