# Модуль E — News Intelligence (тренды, источники, без галлюцинаций)

> **Статус:** ТЗ / проектирование  
> **Связь:** [PRODUCT_STATUS.md](./PRODUCT_STATUS.md) · [SCOUT_MODULE.md](./SCOUT_MODULE.md) · [SCOUT_CRM.md](./SCOUT_CRM.md)  
> **Для кого:** новостные и новостно-аналитические каналы (+ позже — любые ниши с «что сейчас в тренде»)

---

## 1. Проблема

Сейчас бот собирает **посты канала**: текст, просмотры, реакции (если доступны). Этого мало для новостника:

| Вопрос | Сейчас | Нужно |
|--------|--------|-------|
| Что в тренде? | ❌ | Кластер «одна новость — N каналов» |
| Откуда новость? | ❌ | Первоисточник (РИА, ТАСС, ссылка в посте) |
| Актуально ли? | ❌ | Возраст факта, уже все выложили? |
| Достоверно ли? | ❌ | Цепочка источников, не выдумка LLM |
| Написать пост «как у них» | LLM гадает | LLM **только переписывает проверенные факты** |

**Ключевой инсайт:** новостные каналы **не придумывают** новости — они **переупаковывают** одни и те же сюжеты с разной подачей. Значит, мы можем:

1. Следить за **пулом каналов-конкурентов** в нише.
2. **Кластеризовать** похожие посты → «сюжет дня».
3. Вытащить **первоисточник** (ссылка, агентство, время).
4. Генерировать пост **только из карточки фактов**, не из головы модели.

> **LLM не «обучается постоянно» в смысле fine-tune.** Она **не галлюцинирует**, когда работает в режиме: *«вот 5 проверенных буллетов со ссылками — перепиши в стиле канала X»*. Обучение = растущая **база фактов + бенчмарки стиля + исходы** (RAG), а не дообучение весов.

## 3. Архитектура

```

│  Watchlist: 20–100 новостных каналов в нише (TGStat + scrape)    │
└────────────────────────────┬────────────────────────────────────┘
                             │ каждые 15–30 мин
┌────────────────────────────▼────────────────────────────────────┐
│  Ingest: посты + ссылки + время + просмотры                      │
└────────────────────────────┬────────────────────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
  StoryClusterer      SourceExtractor      TrendScorer
  (похожие посты      (URL → домен,        (velocity,
   = один сюжет)       RSS, агентство)      охват, свежесть)
        │                    │                    │
        └────────────────────┼────────────────────┘
                             ▼

                    news_facts (буллеты + source_url)
                             │

              ┌──────────────────────────────┐

              │  1) facts only → draft         │
              │  2) FactGuard: сверка с фактами│
              └──────────────────────────────┘
```

## 4. Слой достоверности (откуда брать правду)

### 4.1. Источники фактов (приоритет)

| Уровень | Источник | Доверие |
|---------|----------|---------|
| **S0** | Официальные: cbr.ru, gov.ru, пресс-релизы компаний | Максимум |
| **S1** | Агентства: ТАСС, РИА, Интерфакс (RSS/API) | Высокое |
| **S2** | Ссылка **внутри поста** канала → парсинг оригинала | Среднее (зависит от домена) |
| **S3** | Первый канал в кластере, у кого максимальный охват + есть ссылка | Низкое-среднее |
| **S4** | Только текст поста без ссылки | **Запрещено для генерации** — только «сюжет есть, фактов нет» |

### 4.2. Source Extractor

Для каждого поста:

1. Распарсить `href` из текста (t.me не отдаёт — из полного текста / TGStat posts).
2. Классифицировать домен: `whitelist` (доверенные), `graylist`, `blocklist`.
3. Опционально: **fetch заголовка + lead** оригинальной страницы (Jsoup, с лимитами).
4. Записать в `news_facts`: `{ claim, source_url, extracted_at, trust_level }`.

### 4.3. Внешние ленты (ground truth)

Подключить **RSS/API** по нише (не только Telegram):

```yaml
news:
  rss-feeds:
    - url: https://ria.ru/export/rss2/index.xml
      trust: S1
    - url: https://www.cbr.ru/rss/RssPress
      trust: S0
  refresh-minutes: 30
```

Сюжет из Telegram **склеивается** с RSS: если заголовок похож (embedding / ключевые слова) — факты берём из RSS как эталон.

## 5. Кластеризация «одна новость — много каналов»

**Алгоритм (без магии):**

1. Каждые N минут — новые посты из watchlist.
2. Нормализация: убрать эмодзи, lower, стоп-слова.
3. **SimHash / embedding cosine** между заголовками (первые 200 символов).
4. Порог similarity > 0.82 → один `story_id`.
5. В кластере хранить:
   - `first_seen_at`, `channels_count`, `max_views`, `example_posts[]`
   - `keywords`, `entities` (NER: компании, персоны — опционально)

**Тренд-скор:**

```
trend_score = channels_count * 2
            + log(avg_views) * 1.5
            + freshness_bonus  # < 3 ч = +10, < 12 ч = +5
            - already_old_penalty  # > 48 ч без роста = -20
```

## 6. Актуальность

| Статус | Условие | Действие |
|--------|---------|----------|
| 🔥 Горячо | < 6 ч, ≥ 5 каналов | Предлагать писать |
| ⚡ Актуально | < 24 ч | Можно, с пометкой |
| 🧊 Устарело | > 48 ч или все крупные уже выложили | «Опоздали — не рекомендуем» |
| ♻️ Перепост | Кластер без новых фактов 24+ ч | Предложить **угол**, не копию |

**Детектор «все уже выложили»:** если в watchlist > 70% каналов ниши уже имеют пост в кластере и median_views падает — сюжет «выжжен».

## 7. Генерация без галлюцинаций (обязательный пайплайн)

### Шаг 1 — Карточка фактов (не LLM)

```json
{
  "story_id": "uuid",
  "title": "ЦБ повысил ключевую ставку",
  "facts": [
    { "text": "Ставка X% с даты Y", "source": "https://cbr.ru/...", "trust": "S0" },
    { "text": "Предыдущая ставка Z%", "source": "https://cbr.ru/...", "trust": "S0" }
  ],
  "style_reference_channel": "@user_channel",
  "forbidden": ["добавлять цифры не из facts", "выдумывать цитаты"]
}
```

Если `facts.length < 1` с trust ≤ S2 → **генерация запрещена**, только: «Недостаточно проверенных источников».

### Шаг 2 — LLM: переписать, не придумать

```
SYSTEM: Ты редактор. Используй ТОЛЬКО facts[].text.
Каждое число должно совпадать с facts. В конце — строка «Источники: …».
Если facts мало — ответь REFUSE и причину.

USER: Стиль как у канала (примеры топ-постов): …
Facts: …
Напиши пост до 800 символов.
```

### Шаг 3 — FactGuard (второй проход LLM или правила)

- Извлечь все числа/даты/имена из черновика.
- Сверить с `facts[]`.
- Лишнее → `HALLUCINATION_RISK` → не показывать пользователю, запросить правку или урезать.

### Шаг 4 — Человек / автопост

- Черновик в боте с кнопками: **Опубликовать / Править / Отклонить**.
- Feedback → `generation_outcomes` для улучшения промптов (не весов модели).

## 8. «Обучение» без fine-tune

| Что копится | Зачем |
|-------------|-------|
| `news_stories` + исходы (опубликовали / пропустили) | Какие сюжеты конвертят в просмотры |
| `source_trust_scores` | Какие домены чаще совпадают с S0/S1 |
| `channel_style_profiles` | Тон, длина, эмодзи — **отдельно от фактов** |
| `successful_posts` | Few-shot для стиля, не для фактов |
| `refused_generations` | Где не хватило источников — улучшать ingest |

**Принцип:** стиль учится на канале пользователя; **факты — только из внешних источников и ссылок**.

## 9. Интеграция с текущим ботом

| Сейчас | Добавляем |
|--------|-----------|
| Анализ одного канала | + watchlist ниши (5–50 каналов) |
| Идеи «с головы» | + «Идеи из трендов» (только со story_id) |
| Скрейпинг t.me/s/ | + TGStat posts (ссылки), RSS sidecar |
| LLM разбор | + блок «Что сейчас в тренде в вашей нише» |

**Новые команды (или раздел в отчёте):**

- `📰 Тренды` — топ-5 сюжетов за 24 ч
- `✍️ Пост по сюжету #3` — черновик с FactGuard
- `🔍 Откуда новость` — цепочка каналов + первоисточник

## 10. Схема БД (черновик)

```sql
news_watch_channels (id, username, niche, priority, added_at);

news_ingested_posts (
  id, channel_username, message_id, text, views,
  published_at, links_json, ingested_at
);

news_stories (
  id, headline, niche, cluster_key,
  channels_count, trend_score, status ENUM('HOT','WARM','STALE','BURNED'),
  first_seen_at, last_seen_at
);

news_story_posts (story_id, ingested_post_id);

news_facts (
  id, story_id, claim_text, source_url, trust_level,
  extracted_at, verified BOOLEAN
);

news_generation_drafts (
  id, story_id, user_channel_id, draft_text,
  fact_guard_status ENUM('OK','RISK','REFUSED'),
  sources_cited, created_at
);
```

## 11. Фазы разработки

| Фаза | Срок | Результат |
|------|------|-----------|
| **E0** | 1 нед | Watchlist + ingest нескольких каналов, парсинг ссылок |
| **E1** | 1 нед | Кластеризация сюжетов + trend_score |
| **E2** | 1 нед | RSS-ленты S0/S1 + склейка с Telegram-кластерами |
| **E3** | 1 нед | Карточка фактов + generate с REFUSE если нет источников |
| **E4** | 3 дня | FactGuard + блок в отчёте «Тренды» |
| **E5** | 1 нед | Обратная связь, trust scores доменов, дайджест «что писать сегодня» |

**Зависимости:** TGStat API (posts + ссылки), Модуль A (ниши), опционально Observer-скауты.

---

## 12. Риски и честные ограничения

| Риск | Реальность |
|------|------------|
| «LLM постоянно обучается» | Fine-tune дорого и не нужен; **RAG + факты + FactGuard** |
| Нет ссылки в посте | Факт не подтверждён → не генерируем |
| Фейковые новости в источнике | Whitelist доменов + пометка «не проверено» |
| Опоздали с сюжетом | Явный статус STALE / BURNED |
| Стоимость | Ingest фоновый; LLM только на финальный черновик (1 вызов + 1 FactGuard) |

---

## 13. Связь со скаутами

- **Observer-скауты** в новостных чатах → ранний сигнал (что обсуждают до постов).
- **Watchlist** новостных каналов → основной сигнал для кластеров.
- Вместе: «в чатах уже спорят» + «12 каналов выложили» = высший trend_score.
